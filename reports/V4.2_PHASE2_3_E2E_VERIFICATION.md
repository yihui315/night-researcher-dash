## 2. 真实 E2E 暴露并修复的两个后端缺陷

### 2.1 D1 不接受 BigInt（`run2` 发现）

- 现象：`POST /api/paper/orders` → `503 PAPER_ORDER_FAILED: D1_TYPE_ERROR: Type 'bigint' not supported for value '20000'`。
- 根因：`0003_fixed_point.sql` 将金额列改为 `INTEGER`（实际值 × 1e8），`D()` 返回 BigInt；
  `orderRow()` / `fillRow()` 把 BigInt 直接传给 D1 `.bind()`，而 D1 只接受 Number/String/Null。
- 修复：`functions/_lib/paper-server.mjs` 新增 `d1BindValues(values)`，仅做类型桥接
  BigInt 缩放整数 → Number 缩放整数；`Number.isSafeInteger` 失败时显式抛
  `D1_FIXED_POINT_OUT_OF_SAFE_RANGE`，**绝不静默丢精度**。`orderRow()` / `fillRow()` 返回值统一经过该桥接。
- 语义不变：数值仍是 1e8 缩放定点整数，账户规模远小于 2^53。

### 2.2 Workers fetch 不支持 `cache` 字段（`run3` 发现）

- 现象：BigInt 修复后订单可写库，但返回 `409 REJECTED`，
  `rejection.code = "The 'cache' field on 'RequestInitializerDict' is not implemented."`。
- 根因：`fetchJson()` 使用浏览器 Fetch 规范的 `{ cache: "no-store" }`；
  Cloudflare Workers / miniflare 的 `RequestInit` 未实现该字段，导致服务端拉取 Binance 盘口直接抛错。
- 修复：移除 `cache` 字段，改用标准 `cache-control: no-store, max-age=0` 请求头，
  与仓库内 `agent-orchestrator.mjs` / `ai-core.mjs` / `paper-ledger.mjs` 的既有写法一致。
  Workers `fetch` 本身不做隐式缓存，语义等价。

### 2.3 配置一致性

- `wrangler.toml` 原 `binding = "DB"`，但全部服务端代码只读 `env.PAPER_DB`，
  本地 `wrangler dev` 下该 binding 为 undefined → 所有 `/api/paper/*` 503。
  改为 `binding = "PAPER_DB"` 并补 `migrations_dir = "migrations"`。
- `dist/` 由 `dashboard/` 复制，供 Pages dev 提供静态资产。
- `.gitignore` 增加 `.dev.vars`、`.env*`、`/dist/`、`.wrangler/`、`/e2e-artifacts/`。
