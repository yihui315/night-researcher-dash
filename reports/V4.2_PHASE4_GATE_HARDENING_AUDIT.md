## Scope

This change is a safety prerequisite for PHASE 4 Step 2. It does not claim to implement server-side backtest recomputation, OOS verification, scheduled evaluation, or Provider Center integration.

## Findings and changes

1. **Fail-open when account performance was unavailable**
   - Previous behavior could calculate `ELIGIBLE` from verified backtest/OOS rows even when the performance query failed and returned `null`.
   - The gate now requires a non-empty server-side account set, the expected trusted source, a valid drawdown field, and `riskBasis=mark-to-market-equity-snapshots`.
   - Missing or mismatched performance evidence fails closed and blocks Kelly sizing.

2. **Realized PnL is not mark-to-market drawdown**
   - The current `paper_fills` calculation only reconstructs realized PnL after fees. It does not capture the equity path while positions are open.
   - The current performance calculation is explicitly labelled `riskBasis=realized-pnl-only`.
   - The final strategy release gate deliberately rejects this basis until server-side equity snapshots are implemented. This is intentional; do not change the gate to accept realized-only statistics.

3. **Account reset and rolling-window baseline**
   - Performance reconstruction now reads the latest `paper.server.account.reset` event per session.
   - Fills from earlier account generations are excluded.
   - Realized PnL before the requested rolling window, but after the latest reset, is carried into the window-start baseline.
   - Invalid account state, timestamps, fixed-point values, or depleted baselines fail closed.

4. **Daily drawdown aggregation**
   - Daily maximum drawdown now retains the maximum intraday drawdown rather than being overwritten by a later recovery.

5. **Evidence lineage**
   - The evaluate endpoint now selects backtest and OOS records from the same `research_runs.run_id` and exact registered strategy version.
   - Research-run listing reports `evidenceThresholdsMet`; it no longer implies that backtest/OOS evidence alone is final release approval.
   - Final approval still requires the account-risk gate. Promotion and automatic execution remain disabled.
