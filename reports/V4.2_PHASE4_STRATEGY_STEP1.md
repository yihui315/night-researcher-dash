### 2.2 服务端库 `functions/_lib/strategy-registry.mjs`

硬约束：

- **不接受客户端上报绩效/OOS 指标**。所有 HTTP 端点只读这些表；`verified=1`
  只能由未来的服务端原始成交重算任务设置。
- **绩效只从真实 `paper_fills` 计算**，账户基线取自 `paper_accounts.state_json.initialCash`。
- `evaluateStrategyGate()` 纯确定性：无版本 / 未冻结 / 无 `verified=1` 回测 /
  无 `verified=1` OOS / 样本数 <100 / OOS 交易 <30 / 真实回撤 >20% → 一律不放行。
- 失败时写 append-only `risk_rejections`，并 emit 已在白名单中的 `strategy.gate.rejected`
  可信事件；活跃生命周期（backtest/oos/paper）失败会置 `lifecycle='suspended'`。
- **即使 ELIGIBLE 也不自动晋级、不下单、不改 `autoExecution`**；TAKER 保持 PROPOSAL_ONLY。
- `buildKellyMetrics()` 是未来接通 `computeFractionalKelly(metrics)` 的服务端取数口，
  当前因无 verified 数据恒返回 BLOCKED。

### 真实 E2E 发现并修复的缺陷

run1 中首笔成交为亏损时 `max_drawdown_pct = 0`：权益峰值在第一行成交**之后**才初始化，
把亏损后的净值当成峰值，会使 20% 回撤自动暂停闸门在最该触发时失效。
修复为**用交易前的 baseline 预置峰值**，新增回归测试
「a losing FIRST fill must produce a non-zero drawdown」，并在 run2 真实 D1 上验证
`max_drawdown_pct=80 > 0`。run1 原始证据保留，未改成 PASS。
