## 4. 数据完整性证明

- 证据包 seal：`canonical_payload` 由 Python 生成并随包携带，服务端对该**确切字节**求 sha256 后以解析结果作为权威数据源，规避 Python/JS 浮点格式差异；HMAC 再绑定原始请求体字节（双重）。
- D1 原子性：单次 `db.batch()` 覆盖 5 类语句（`atomicBatchStatements=5`），要么全落要么全不落。
- 版本绑定：`strategy_versions.source_sha256` 必须等于证据包 `strategy_source_sha256`，`version` 相等且 `frozen=1`；任一不符 `verified=0`。
- 拒绝客户端自报：若 `strategy_pass=1` 但 `sample_count<100` / `overfit_suspect=1` / OOS 净收益为负，直接 422 `SELF_REPORTED_PASS_CONTRADICTS_METRICS`。
- 交易回放链：`replay.verified=true` 且 `lastSequence` 前后一致（12→12），证明 V4.3 的快照/验证/策略事件均未污染原状态哈希链。

## 5. 本轮发现并修复的真实缺陷（均来自真实运行，非推测）

1. **权益峰值初始化**（E2E run1）：`buildEquityRiskBasis()` 峰值从 0 起算，第一条含手续费亏损的快照被当成峰值 → `max_drawdown_pct=0`，20% 自动暂停闸门会静默失效。修复：使用服务端快照中已由 `initialCash` 预置的 `equity_peak`；新增回归单测 + E2E 断言，run2/run3 验证非零。
2. **nonce 同毫秒重放误判**（全量单测 134/135）：`consumeNonce()` 用「本次 ISO 时间字符串相等」判断是否是自己创建的行，两次请求落在同一毫秒会把重放误判为首次。修复：`SELECT` 存在性 + `PRIMARY KEY` 唯一约束兜底，不再依赖时间戳。
3. **定点数二次缩放**（单测阶段）：`D(number)` 会把数字当实际值放大 1e8，而 D1 历史峰值已是 1e8 定点整数；改为 `BigInt()` 还原并加回归测试。
4. **`wrangler` 回滚脚本误入 migrations/**（设计阶段发现）：回滚 SQL 若放在 `migrations/` 会被 `d1 migrations apply` 自动执行并 DROP 表，已刻意置于 `scripts/`。

失败证据 run1/run2 全部保留，未改标 PASS。
